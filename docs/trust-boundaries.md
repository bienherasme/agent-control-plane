# Trust boundaries

This document states, precisely, what Agent Control Plane trusts, what it treats as untrusted
observed data, and what it deliberately makes no claim about.

## A. Producer-supplied execution data

Everything a producer reports through an `ExecutionEvent` (step names, capability identity,
model identity, human interaction outcomes, decision values, timestamps) is untrusted observed
data. Typed Pydantic validation constrains its shape (non-blank identifiers, timezone-aware
timestamps, closed enums for lifecycle/kind/mode), but the control plane does not verify that
the reported facts are true of the outside world. There is no mechanism anywhere for observed
data to become an executable policy, query, or expression; the fields a producer supplies are
data, never code.

## B. Event identity

`event_id` and `occurred_at` are producer-supplied, not generated by the control plane. Exact
duplicate content under the same `event_id` is treated as the same event for idempotency
purposes; this is a retry-safety mechanism, not a cryptographic identity or authenticity claim.
The control plane does not sign, verify, or otherwise attest to who actually emitted an event.

## C. Model metadata

`ModelInvocation` carries only provider/model/operation identity and input/output usage counts.
There is no field for a raw prompt, a raw response, or chain-of-thought/reasoning content
anywhere in the domain, and none is ever accepted, stored, or displayed. This is an intentional
privacy and trust boundary, not an oversight: the control plane observes that a model was
invoked and roughly how much it used, not what was said.

## D. Human interaction

`actor_reference` on a `HumanInteraction` is an opaque, caller-owned string. There is no built-in
user identity, authentication, or authorization system anywhere in the core. A completed `HUMAN`
step with an accepted outcome is observed data reported by the producer; it is not cryptographic
proof that a specific person approved anything, and governance's approval policy treats it
exactly as that: an observed fact, sequenced logically, nothing more.

## E. Policies and expectations

`GovernancePolicySet` and `EvaluationExpectationSet` are trusted, caller-supplied configuration,
loaded from files the operator controls. Observed execution data can never redefine a policy or
an expectation: there is no `eval`, no expression language, and no mechanism for a string that
arrived through an event to be interpreted as a rule. Policy and expectation filters use exact,
case-sensitive string matching only.

## F. Governance

Governance is observational. A `VIOLATION` records that observed behavior violated a configured
policy; it does not mean the control plane intercepted, blocked, or could have blocked the
underlying action. There is no enforcement path anywhere in this codebase, and none is implied
by a violation result.

## G. SQLite

`SQLiteExecutionEventStore` is a local reference adapter. It assumes the underlying filesystem
and SQLite installation preserve what they durably commit; the control plane does not implement
its own checksumming or replication on top of that. If a persisted row cannot be deserialized
into a valid typed event, or a stream's own invariants fail to reconstruct, the store raises
`ExecutionEventStoreError` rather than returning a partial or repaired stream. There is no
automatic repair tooling.

## H. CLI input files

Event JSON passed to `ingest`, and policy/expectation JSON passed to `report`/`compare`, are
untrusted input validated through the real Pydantic models before use. There is no YAML, no
TOML, and no policy expression language accepted anywhere in the CLI; invalid input is rejected
with a concise error, never partially applied.

## I. Secrets

The project does not manage secrets. The core has no field, configuration option, or code path
for a model provider API key, a database credential beyond a local filesystem path, or any other
secret. Nothing in this repository requires one to run.
